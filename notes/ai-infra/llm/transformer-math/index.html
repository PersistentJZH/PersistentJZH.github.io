Transformer 的数学原理与完整推导

约 11024 字大约 37 分钟

2026-11-09

Transformer 把 token 序列变成向量，通过注意力交换不同位置的信息，再把每个位置的向量映射成预测分数。对自回归语言模型来说，最后一个位置的分数用于选择下一个 token；把它追加到输入后，就可以继续生成。

先看原始 Transformer 的整体架构：左侧 encoder 处理源序列，右侧 decoder 结合源序列和已有的目标序列，预测下一个 token。

图 1：原始 Transformer 的 encoder-decoder 架构，从下向上阅读。图中的 n×n\timesn× 表示该组模块重复堆叠的层数，与本文用 nnn 表示的序列长度含义不同。图源：《动手学深度学习》图 11.7.1，作者团队原图，按 CC BY-SA 4.0 使用。

沿箭头从下往上读：底部把 token 变成向量并加入位置信息，中间反复经过注意力、前馈网络、残差连接与归一化，顶部 FC 将最终特征映射成词表分数，再通过 softmax 得到预测概率；图中省略了最后的 softmax。

后面的数值例子采用 单层、decoder-only、Post-LN Transformer，保留右侧的因果自注意力、FFN 及其残差和归一化，省去左侧 encoder 和连接两侧的 cross-attention。本例用手动指定的权重演示计算流程。

下面按“输入 → 注意力 → 完整 block → 词表概率”的顺序展开，再分别说明训练如何更新参数、推理如何逐个生成 token。

部分要回答的问题参数是否变化
共同前向给定输入和参数，怎样算出各位置的预测概率？本次计算中固定
训练怎样用正确答案修正参数？优化器更新参数
推理怎样用已有参数连续生成 token？参数固定，输入逐轮增长

1. 共同部分：一次前向计算

1.1 模型到底在计算什么

设输入 token 为 x1,…,xnx_1,\ldots,x_nx1​,…,xn​。模型计算：

pθ(xn+1∣x1,…,xn)p_\theta(x_{n+1}\mid x_1,\ldots,x_n) pθ​(xn+1​∣x1​,…,xn​)

其中 θ\thetaθ 表示模型参数。输出是整个词表上的概率分布，随后才由解码策略选择一个 token。

1.2 从 token 到输入矩阵

1.2.1 Embedding 是一次查表

规定 token ID 为：我=0、爱=1、你=2、<eos>=3、学习=4。每个词表项用四维向量表示，指定 5×45\times45×4 的 embedding 表：

1.3 从点积推导注意力

每个 token 用多少个数表示，由模型的隐藏维度 ddd 决定；序列包含多少个 token，则由长度 nnn 决定。这是两个独立的量：

X∈Rn×d,XX⊤∈Rn×nX\in\mathbb R^{n\times d},\qquad XX^\top\in\mathbb R^{n\times n} X∈Rn×d,XX⊤∈Rn×n

例如，五个 token、每个向量 4096 维时，XXX 的形状是 5×40965\times40965×4096，匹配矩阵仍是 5×55\times55×5。每个匹配分数由两条 4096 维向量的点积得到。

1.4.1 为什么要有多个头

回看五个 token 的例子：计算“家”的新向量时，给“今天”的权重约为 0.174878，于是“今天”向量中的四个分量都乘以 0.174878。换成 O=AVO=AVO=AV 后也是如此：对于当前要更新的位置，同一个来源词的所有 Value 分量共用一个权重。

训练从同一条前向计算开始。区别在于：训练文本已经给出了每个位置的正确答案，我们可以衡量预测误差，再把误差反传到参数。

2.1 输入和标签如何对应

沿用主算例的词表，假设完整训练序列为 我 爱 你 <eos>。把前三个 token 作为输入，后三个 token 作为标签：

输入：我    爱    你
