# How OpenKruise In-Place Updates Work

## What Is an In-Place Update?

In-place updates are a Pod update strategy provided by OpenKruise. They update container images and certain other fields without deleting the Pod. Compared with the recreation-based updates native to Kubernetes, in-place updates offer the following benefits:

### Traditional Recreation-Based Updates vs. In-Place Updates

| Feature | Traditional recreation-based update | In-place update |
|------|--------------|----------|
| Pod name | Changes (recreated) | Unchanged |
| Pod UID | Changes | Unchanged |
| Pod IP | Changes | Unchanged |
| Update speed | Slower (requires scheduling and image pulls) | Faster (only restarts containers) |
| Volumes | Must be remounted | Remain mounted |
| Network connections | Interrupted | Can be preserved in some scenarios |
| Reserved resources | May be taken by other Pods | Always retained |

## Core Principles

### 1. Pod Update Mechanism

OpenKruise extends the Kubernetes Pod specification with special annotations and labels that control the in-place update process:

#### Key Annotations

```yaml
metadata:
  annotations:
    # Mark the Pod as requiring an in-place update
    apps.kruise.io/inplace-update-state: '{"containerImages":{"nginx":"nginx:1.19"}}'

    # Record the in-place update revision
    apps.kruise.io/inplace-update-grace: '{"revision":"cloneset-abc123","containerImages":{"nginx":"nginx:1.19"}}'
```

### 2. Update Workflow

The complete in-place update workflow consists of the following stages:

```
┌─────────────────────────────────────────────────────────────────┐
│                     In-Place Update Workflow                      │
└─────────────────────────────────────────────────────────────────┘

1. PreCheck stage
   ├─ Check whether the Pod meets the requirements for an in-place update
   ├─ Check whether the updated fields are supported (images, environment variables, etc.)
   └─ Verify that the Pod is healthy

2. Prepare stage
   ├─ Add in-place update annotations to the Pod
   ├─ Mark the Pod NotReady (remove it from Service Endpoints)
   └─ Wait for gracePeriod (the graceful termination period)

3. Update stage
   ├─ Update the target fields in the Pod Spec
   │  ├─ Container images
   │  ├─ Environment variables
   │  └─ Resource limits (partially supported)
   ├─ Kubelet detects changes to the Pod Spec
   └─ Kubelet restarts the affected containers

4. PostCheck stage
   ├─ Wait for the containers to restart
   ├─ Check container health probes
   ├─ Remove the in-place update annotations
   └─ Restore the Pod to Ready
```

### 3. Implementation Details

#### 3.1 How Kubelet Restarts Containers

In-place updates use Kubelet's existing capabilities. When a container image in the Pod Spec changes, Kubelet performs the following steps:

```go
// Pseudocode for Kubelet detecting changes to the Pod Spec
func (kl *Kubelet) syncPod(pod *v1.Pod) error {
    // 1. Get the current Pod status
    podStatus := kl.statusManager.GetPodStatus(pod.UID)

    // 2. Compare the desired and current states
    for _, container := range pod.Spec.Containers {
        currentContainer := findContainer(podStatus, container.Name)

        // 3. If the images differ, stop and restart the container
        if currentContainer.Image != container.Image {
            // Stop the old container
            kl.containerRuntime.KillContainer(currentContainer.ID, gracePeriod)

            // Pull the new image
            imageRef := kl.imagePuller.EnsureImageExists(container.Image)

            // Start the new container
            kl.containerRuntime.StartContainer(pod, container, imageRef)
        }
    }

    return nil
}
```

#### 3.2 Fields That Support In-Place Updates

OpenKruise supports in-place updates to the following fields:

```yaml
# ✅ Fields that support in-place updates
spec:
  containers:
  - name: app
    image: nginx:1.19  # ✅ Container image
    env:               # ✅ Environment variables
    - name: LOG_LEVEL
      value: "info"
    resources:         # ⚠️ Partially supported (requires Kubernetes 1.27+)
      limits:
        cpu: "2"
        memory: "2Gi"

# ❌ Fields that do not support in-place updates
spec:
  volumes:           # ❌ Volume definitions
  nodeSelector:      # ❌ Node selector
  affinity:          # ❌ Affinity configuration
  serviceAccountName: # ❌ Service account
```

### 4. State Machine Model

During an in-place update, a Pod transitions through several states:

```go
type InPlaceUpdateState string

const (
    // No update needed
    InPlaceUpdateStateNone InPlaceUpdateState = ""

    // Preparation: remove from the Service and wait for graceful shutdown
    InPlaceUpdateStatePreparing InPlaceUpdateState = "Preparing"

    // Updating: containers are being updated
    InPlaceUpdateStateUpdating InPlaceUpdateState = "Updating"

    // Updated: containers have been updated and are awaiting health checks
    InPlaceUpdateStateUpdated InPlaceUpdateState = "Updated"
)
```

State transition diagram:

```
     ┌──────┐
     │ None │
     └───┬──┘
         │ Update triggered
         ▼
  ┌──────────────┐
  │  Preparing   │  (NotReady, graceful shutdown)
  └──────┬───────┘
         │ gracePeriod ends
         ▼
  ┌──────────────┐
  │   Updating   │  (update the Pod Spec)
  └──────┬───────┘
         │ Container restart completes
         ▼
  ┌──────────────┐
  │   Updated    │  (wait for health checks)
  └──────┬───────┘
         │ Health checks pass
         ▼
     ┌──────┐
     │ None │  (Ready, added to the Service)
     └──────┘
```

## A Deeper Look at the Source Code

### 1. Core CloneSet Controller Logic

```go
// pkg/controller/cloneset/sync/cloneset_update.go

func (r *ReconcileCloneSet) updatePods(cloneSet *appsv1alpha1.CloneSet, pods []*v1.Pod) error {
    // 1. Calculate which Pods need updating
    podsToUpdate := r.getPodsToUpdate(cloneSet, pods)

    for _, pod := range podsToUpdate {
        // 2. Check whether an in-place update is possible
        if canInPlaceUpdate(pod, cloneSet.Spec.Template) {
            // 3. Perform the in-place update
            if err := r.inPlaceUpdatePod(pod, cloneSet); err != nil {
                return err
            }
        } else {
            // 4. Fall back to a recreation-based update
            if err := r.recreatePod(pod); err != nil {
                return err
            }
        }
    }

    return nil
}

func (r *ReconcileCloneSet) inPlaceUpdatePod(pod *v1.Pod, cloneSet *appsv1alpha1.CloneSet) error {
    // Get the current in-place update state
    state := inplaceupdate.GetInPlaceUpdateState(pod)

    switch state {
    case inplaceupdate.InPlaceUpdateStateNone:
        // Stage 1: start the in-place update and set the state to Preparing
        return r.prepareInPlaceUpdate(pod, cloneSet)

    case inplaceupdate.InPlaceUpdateStatePreparing:
        // Stage 2: check whether gracePeriod has elapsed
        if time.Now().After(state.GraceStartTime.Add(gracePeriod)) {
            return r.executeInPlaceUpdate(pod, cloneSet)
        }
        return nil

    case inplaceupdate.InPlaceUpdateStateUpdating:
        // Stage 3: wait for the containers to restart
        if allContainersReady(pod) {
            return r.completeInPlaceUpdate(pod)
        }
        return nil
    }

    return nil
}

func (r *ReconcileCloneSet) prepareInPlaceUpdate(pod *v1.Pod, cloneSet *appsv1alpha1.CloneSet) error {
    // 1. Add the in-place update annotation
    if pod.Annotations == nil {
        pod.Annotations = make(map[string]string)
    }

    updateState := &inplaceupdate.InPlaceUpdateState{
        Revision:        cloneSet.Status.UpdateRevision,
        ContainerImages: getNewContainerImages(cloneSet),
        State:           "Preparing",
        GraceStartTime:  time.Now(),
    }

    data, _ := json.Marshal(updateState)
    pod.Annotations[inplaceupdate.InPlaceUpdateStateKey] = string(data)

    // 2. Set the Pod to NotReady (by adding a ReadinessGate)
    pod.Spec.ReadinessGates = append(pod.Spec.ReadinessGates, v1.PodReadinessGate{
        ConditionType: inplaceupdate.InPlaceUpdateReady,
    })

    // 3. Update the Pod
    return r.Client.Update(context.TODO(), pod)
}

func (r *ReconcileCloneSet) executeInPlaceUpdate(pod *v1.Pod, cloneSet *appsv1alpha1.CloneSet) error {
    // 1. Update the container images in the Pod Spec
    for i, container := range pod.Spec.Containers {
        newImage := getNewImage(cloneSet, container.Name)
        if newImage != "" {
            pod.Spec.Containers[i].Image = newImage
        }
    }

    // 2. Set the in-place update state to Updating
    updateState := getInPlaceUpdateState(pod)
    updateState.State = "Updating"
    data, _ := json.Marshal(updateState)
    pod.Annotations[inplaceupdate.InPlaceUpdateStateKey] = string(data)

    // 3. Update the Pod (trigger Kubelet to restart the containers)
    return r.Client.Update(context.TODO(), pod)
}

func (r *ReconcileCloneSet) completeInPlaceUpdate(pod *v1.Pod) error {
    // 1. Remove the in-place update annotation
    delete(pod.Annotations, inplaceupdate.InPlaceUpdateStateKey)

    // 2. Remove the ReadinessGate
    pod.Spec.ReadinessGates = removeReadinessGate(pod.Spec.ReadinessGates,
                                                   inplaceupdate.InPlaceUpdateReady)

    // 3. Update the Pod
    return r.Client.Update(context.TODO(), pod)
}
```

### 2. Determining Whether an In-Place Update Is Possible

```go
func canInPlaceUpdate(oldPod *v1.Pod, newTemplate *v1.PodTemplateSpec) bool {
    oldSpec := &oldPod.Spec
    newSpec := &newTemplate.Spec

    // Check fields that cannot be updated in place
    checks := []struct {
        name  string
        equal bool
    }{
        {"Volumes", apiequality.Semantic.DeepEqual(oldSpec.Volumes, newSpec.Volumes)},
        {"InitContainers", canUpdateInitContainers(oldSpec.InitContainers, newSpec.InitContainers)},
        {"EphemeralContainers", apiequality.Semantic.DeepEqual(oldSpec.EphemeralContainers, newSpec.EphemeralContainers)},
        {"Overhead", apiequality.Semantic.DeepEqual(oldSpec.Overhead, newSpec.Overhead)},
        {"Affinity", apiequality.Semantic.DeepEqual(oldSpec.Affinity, newSpec.Affinity)},
        {"NodeSelector", apiequality.Semantic.DeepEqual(oldSpec.NodeSelector, newSpec.NodeSelector)},
        {"ServiceAccountName", oldSpec.ServiceAccountName == newSpec.ServiceAccountName},
    }

    for _, check := range checks {
        if !check.equal {
            klog.V(4).Infof("Cannot in-place update because %s changed", check.name)
            return false
        }
    }

    // Check container updates
    for i := range newSpec.Containers {
        oldContainer := findContainer(oldSpec.Containers, newSpec.Containers[i].Name)
        if oldContainer == nil {
            return false  // Adding a container is not supported for in-place updates
        }

        if !canUpdateContainer(oldContainer, &newSpec.Containers[i]) {
            return false
        }
    }

    return true
}

func canUpdateContainer(old, new *v1.Container) bool {
    // Fields that may be updated
    // ✅ Image
    // ✅ Env
    // ✅ Resources (Kubernetes 1.27+)

    // Fields that may not be updated
    // ❌ Name
    // ❌ Ports
    // ❌ VolumeMounts
    // ❌ VolumeDevices
    // ❌ LivenessProbe
    // ❌ ReadinessProbe
    // ❌ StartupProbe

    if old.Name != new.Name {
        return false
    }

    if !apiequality.Semantic.DeepEqual(old.Ports, new.Ports) {
        return false
    }

    if !apiequality.Semantic.DeepEqual(old.VolumeMounts, new.VolumeMounts) {
        return false
    }

    // ... other checks

    return true
}
```

## Best Practices

### 1. When to Use In-Place Updates

**Suitable scenarios:**
- ✅ Updating only container images or environment variables
- ✅ Preserving Pod IPs (for example, services with long-lived connections)
- ✅ Volumes containing large amounts of data (avoid remounting)
- ✅ Fast rollbacks
- ✅ Clusters with limited resources

**Unsuitable scenarios:**
- ❌ Updating unsupported fields such as volumes or affinity
- ❌ Frequent changes to init containers
- ❌ Rescheduling Pods to other nodes

### 2. Configure Health Checks

```yaml
spec:
  containers:
  - name: app
    # Startup probe: ensure the container starts correctly
    startupProbe:
      httpGet:
        path: /health
        port: 8080
      failureThreshold: 30
      periodSeconds: 10

    # Readiness probe: ensure traffic does not reach Pods that are not ready
    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 3

    # Liveness probe: check whether the container is healthy
    livenessProbe:
      httpGet:
        path: /health
        port: 8080
      initialDelaySeconds: 30
      periodSeconds: 10
```

### 3. Set an Appropriate Graceful Shutdown Period

```yaml
spec:
  updateStrategy:
    inPlaceUpdateStrategy:
      gracePeriodSeconds: 30  # Adjust for your application
  template:
    spec:
      terminationGracePeriodSeconds: 30
      containers:
      - name: app
        lifecycle:
          preStop:
            exec:
              command:
              - /bin/sh
              - -c
              - |
                # 1. Stop accepting new requests
                kill -TERM 1
                # 2. Wait for existing requests to finish
                sleep 15
```

### 4. Monitoring and Alerts

### Test Script

```bash
#!/bin/bash

# Test in-place update performance
test_inplace_update() {
    echo "Starting the in-place update test..."
    start_time=$(date +%s)

    # Record the initial state
    kubectl get pods -l app=nginx-demo -o json > before.json

    # Perform the update
    kubectl patch cloneset nginx-demo --type='merge' -p='{
      "spec": {
        "template": {
          "spec": {
            "containers": [{
              "name": "nginx",
              "image": "nginx:1.21.0"
            }]
          }
        }
      }
    }'

    # Wait for the update to complete
    kubectl wait --for=condition=Ready pods -l app=nginx-demo --timeout=300s

    end_time=$(date +%s)
    duration=$((end_time - start_time))

    # Record the final state
    kubectl get pods -l app=nginx-demo -o json > after.json

    # Count IP changes
    ip_changes=$(diff <(jq -r '.items[].status.podIP' before.json | sort) \
                      <(jq -r '.items[].status.podIP' after.json | sort) | wc -l)

    echo "Update complete!"
    echo "Duration: ${duration} seconds"
    echo "IP changes: ${ip_changes}"
}

test_inplace_update
```

## Troubleshooting

### Common Issues

#### 1. A Pod Remains in Preparing

**Cause:** gracePeriod is too long, or the Pod does not respond correctly to SIGTERM.

**Solution:**
```bash
# Check Pod events
kubectl describe pod <pod-name>

# Adjust gracePeriod
kubectl patch cloneset nginx-demo --type='merge' -p='{
  "spec": {
    "updateStrategy": {
      "inPlaceUpdateStrategy": {
        "gracePeriodSeconds": 10
      }
    }
  }
}'
```

#### 2. An In-Place Update Fails and Falls Back to Recreation

**Cause:** A field that does not support in-place updates was changed.

**Check:**
```bash
# View CloneSet events
kubectl describe cloneset nginx-demo

# View logs
kubectl logs -n kruise-system kruise-controller-manager-xxx | grep inplace
```

#### 3. A Container Remains in CrashLoopBackOff

**Cause:** The new image has a problem.

**Solution:**
```bash
# Quick rollback (in-place rollback)
kubectl patch cloneset nginx-demo --type='merge' -p='{
  "spec": {
    "template": {
      "spec": {
        "containers": [{
          "name": "nginx",
          "image": "nginx:1.19.0"  # Roll back to the old version
        }]
      }
    }
  }
}'
```

## Summary

OpenKruise's in-place update is a powerful, elegant feature implemented through the following mechanisms:

1. **Using native Kubernetes capabilities**: making full use of Kubelet's container management mechanism
2. **A carefully designed state machine**: keeping the update process controllable and observable
3. **Flexible strategy configuration**: supporting multiple release strategies, including canary and batch updates
4. **Graceful traffic management**: controlling traffic switching with ReadinessGate

In-place updates provide:
- ✅ **Faster updates** (3–5 times faster)
- ✅ **Lower resource consumption**
- ✅ **More stable network connections**
- ✅ **Simpler operations**

These capabilities make OpenKruise an essential enhancement in the Kubernetes ecosystem.
