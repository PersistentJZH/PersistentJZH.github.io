# Calico IP Pool Usage Example

Calico IP pools can assign independent IP address spaces to different teams.

## Scenario
Suppose a Kubernetes cluster needs separate IP ranges for two teams: development and testing:
- The development team uses 10.0.1.0/24
- The testing team uses 10.0.2.0/24
- Pods use 10.0.0.0/24 by default

## Step 1: Create Multiple IP Pools

First, create three IP pool definition files:

`default-pool.yaml`:
```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: default-pool
spec:
  cidr: 10.0.0.0/24
  blockSize: 26
  ipipMode: Never
  natOutgoing: true
```

`dev-pool.yaml`:
```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: dev-pool
spec:
  cidr: 10.0.1.0/24
  blockSize: 26
  ipipMode: Never
  natOutgoing: true
```

`test-pool.yaml`:
```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: test-pool
spec:
  cidr: 10.0.2.0/24
  blockSize: 26
  ipipMode: Never
  natOutgoing: true
```

Apply these configurations:
```bash
calicoctl apply -f default-pool.yaml
calicoctl apply -f dev-pool.yaml
calicoctl apply -f test-pool.yaml
```

## Step 2: Verify IP Pool Creation

```bash
calicoctl get ippools -o wide
```

The output should resemble:
```
NAME          CIDR          NAT    IPIPMODE   DISABLED
default-pool  10.0.0.0/24   true   Never      false
dev-pool      10.0.1.0/24   true   Never      false
test-pool     10.0.2.0/24   true   Never      false
```

## Step 3: Assign IP Pools to Different Teams

### Method 1: Namespace Annotations

Annotate the development team's namespace:

```bash
kubectl create namespace dev-team
kubectl annotate namespace dev-team \
  cni.projectcalico.org/ipv4pools='["dev-pool"]'
```

Annotate the testing team's namespace:

```bash
kubectl create namespace test-team
kubectl annotate namespace test-team \
  cni.projectcalico.org/ipv4pools='["test-pool"]'
```

### Method 2: Pod Annotations for Finer-Grained Control

Create a Pod for the development team:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: dev-app
  namespace: dev-team
  annotations:
    cni.projectcalico.org/ipv4pools: '["dev-pool"]'
spec:
  containers:
  - name: dev-app
    image: nginx
```

Create a Pod for the testing team:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-app
  namespace: test-team
  annotations:
    cni.projectcalico.org/ipv4pools: '["test-pool"]'
spec:
  containers:
  - name: test-app
    image: nginx
```

## Step 4: Verify IP Allocation

Check the IP addresses assigned to the Pods:

```bash
kubectl get pods -n dev-team -o wide
kubectl get pods -n test-team -o wide
```

Development Pods should receive IPs from 10.0.1.0/24, and testing Pods from 10.0.2.0/24.

## Step 5: Create a Network Policy (Optional)

For stronger isolation, create a NetworkPolicy restricting communication between teams:

`dev-team-policy.yaml`:
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: dev-team-isolation
  namespace: dev-team
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          team: dev
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          team: dev
```

Add labels to the namespaces:

```bash
kubectl label namespace dev-team team=dev
kubectl label namespace test-team team=test
```

## Advanced Example: Node-Specific IP Pools

To make particular nodes use particular IP pools:

1. Add labels to the nodes:
```bash
kubectl label node <node-name> pool-group=high-perf
```

2. Create a dedicated IP pool:
```yaml
apiVersion: projectcalico.org/v3
kind: IPPool
metadata:
  name: high-perf-pool
spec:
  cidr: 10.0.3.0/24
  nodeSelector: pool-group == "high-perf"
  ipipMode: Never
  natOutgoing: true
```

3. Apply the configuration:
```bash
calicoctl apply -f high-perf-pool.yaml
```

Pods scheduled onto nodes labeled `pool-group=high-perf` will then automatically receive IPs from 10.0.3.0/24.

## Clean Up

Delete the example resources:
```bash
kubectl delete namespace dev-team test-team
calicoctl delete ippool default-pool dev-pool test-pool
```
